## Reproduction evidence

`src/world/flows.ts` baseline blob `22f8d375622cc37d8759a050bcbfd19734a53bfa` was hash-checked and transpiled with TypeScript, then executed on Node 22.16.0. Food source 50, destination 99, request 10 produced 40 and 100: total 149 became 140 while the receipt still said 10. Source 1.0004 and destination 2.0004 with request 0.1 lost 0.0008 through independent rounding. NaN contaminated balances; self-transfer quantized state. The capacity example is an executor/replay boundary reproduction; the happy-path deficit planner need not normally produce that request. Ordinary generated fractional balances are still affected by the rounding bug.

The repair keeps planner/runtime signatures unchanged: `CoarseWorldRuntime.runConservedFlows()` already calls the corrected executor. One actual amount is bounded by current available stock and destination room, both proposed balances are checked before either write, and receipts retain actual amount plus original provenance. Authoritative balances are no longer rounded independently. Population is not assigned an invented capacity. Nonfinite, invalid, self/aliased and unrepresentable transfers are no-ops. Numeric conservation assertions explicitly allow IEEE-754 tolerance; this is not an arbitrary-precision ledger.

`tests/flow-conservation.test.ts` adds 14 tests, including 4,000 seeded mixed transfers and raw-total checks. The baseline failed all 14; the repair passed all 14 in the local module test. That module result is not a substitute for full repository typecheck/build/integration or the latest-head browser CI. This fix does not repair the local population-policy edits in #50, the wildlife executor/history in #54, or persistence writer conflicts.

Issue #52 baseline inspection confirmed that `POST /api/world/state` checked only version/meta/coarse/fine envelope fields and `WorldPersistence.save` accepted the typed value directly before opening its transaction. The repair adds one shared unknown-input validator at the storage boundary and routes HTTP saves through it, with temporary-SQLite and real HTTP regressions covering invalid meta/home/coarse/fine wildlife/lineage/transfer facts, bounded counts, actionable paths, logical-table immutability on rejection, and legacy optional fields. This closes input validation only; omission/stale-writer semantics remain #51.

`decisionScheduling.ts` baseline blob `30bfe3e682e696ef9d99ef979738930ebee47359` was also hash-checked and executed. A scheduler-only controlled case with 512 initialized chunks and 8 continuously stressed chunks per 256-ID window ran 1,000 window/rank/adaptive-delay cycles, refreshing successful decision baselines/timestamps. All 512 were scanned, but only 16 served; 496 remained unserved after 7,996,000ms of modeled scheduling time. Capped waiting priority cannot outrank a permanent larger pressure term. This isolates scheduler service fairness; it is not a full-world ecological forecast or an elapsed browser run.

## Planned capabilities and further verification

Richer NPC households, schedules, ownership/social history, economic logistics, true stacking/support and additional licensed movable archetypes, projectile mechanics, save export/backup/recovery, and broader world/region ecology remain roadmap capability work. Do not label their absence as a newly reproduced defect or repeatedly rebuild existing foundations. More detailed collision/entrance alignment, frame-partition determinism and loaded/unloaded ecology equivalence need targeted tests before stronger conclusions. The large integration file `src/main.ts` is a maintenance risk, not a reason for cosmetic refactoring instead of fixes.

## Continuous maintenance loop

Read fresh main, commits, Actions, open PRs/issues, this queue and relevant architecture/physics/persistence docs. Select one complete high-priority slice; reproduce, implement, wire, test, inspect actual browser evidence when applicable, typecheck/build, and accept only latest-head CI. Preserve complete proof in the PR and close only acceptance-complete issues after merge; partial sub-stages leave the parent issue open. Continue another independent complete slice when time permits. Refresh the table if priorities or evidence change. Hourly automation keeps its cadence through tool/CI/review failures and never treats an empty immediate action set as permission to stop the task.
